# 中文回复里的六种问题

每条是一种机制，后面是真实回复里出现过的例子和该怎么写。判断时按机制判，例子帮你认出这种机制。

1. **英文动词直译。** 先有英文动词，再逐字换成中文。例：「抛出 RecursionError」（throw）、「跑完」（run）、「折回 spec」（fold back）、「还挂着等你定」（pending）、「问题还在」（still stands）、「13 条站住」（stand）、「由测试兜住」（catch）、「吐元素」（emit）。该写：报错、运行完、写回、还没定、还没回答、成立、测试会报、取出。
2. **两字动词缩成一个字。** 核对→核、接受→接、推导→推、答得虚→答虚。例：「我自己核过」「我没接的」「它自己也说不推」「写完跑」。该写完整的词。
3. **给新概念造中文名，或把该用英文的技术名词翻成中文。** 例：「烟雾测试」（smoke test）、「dashboard 两个面」（两个页面）、「两个洞」（两处错）、「停车球队」（占位球队）、「票 00」（ticket 00）、「提交进 git」（commit）、「退出码」（exit code）。该写标准英文名、用户已经用过的说法，或者一句大白话。
4. **用颜色或比喻代替结果。** 例：「CI 绿了」「是红是绿」（通过、失败）、「守卫」（guard）、「魔法值」（sentinel value）、「没有牙」（不拦人）。该写字面意思。
5. **英文语序、英文介词，和把英文的检查条件直接当中文句子。** 例：「CI 结果目前不是 dev 的合并条件」（该写「现在 merge 进 dev 不看 CI 结果」）、「基于此」「在……的情况下」。写完成条件时，「bench/results/table.md 存在，退出码 0」是把 file exists、exit code 0 逐条搬过来，中文该先说做成了什么，文件和命令是证据：「Benchmark 的结果已经整理成 bench/results/table.md，每一格都填了数或 missing，`table` 命令能正常生成它」。该先写谁做什么、做成了什么。
6. **催答复、下命令的口气。** 例：「这份 sample 你接受吗」「你认不认」「认了我再……」「写吧。」「你必须选一个」。该写：「你觉得可以吗」「你看有要改的地方吗」，下一步用完整的句子说。

不算问题的：技术名词和动词保留英文（deploy、merge、ticket）；没有现成中文说法的动词和名词也直接用英文，例如「把这条 open question close 掉」比「关门句」清楚；用户自己用过的词；引号里转述别人的原话；code 和链接。引号里的字如果是 agent 自己给东西起的名字或自己的说法，不算转述，照样按机制判，例如「正文里的『洞』全换成『一面答虚的两道题』」里引号内的「答虚」是 agent 自己造的。
